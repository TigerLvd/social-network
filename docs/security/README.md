# Документация по безопасности

Система безопасности проекта social-network построена на токен-based аутентификации. При успешной авторизации пользователь получает токен доступа, который затем используется для доступа к защищенным ресурсам.

---

## 📚 Разделы документации

### [Процесс авторизации (Login)](README_Authorization.md)
Описывает процесс входа пользователя в систему:
- Проверка учетных данных (ID + пароль)
- Генерация и выдача токена доступа
- Компоненты, участвующие в авторизации
- Диаграмма последовательности операций

### [Проверка доступа по токену](README_Access_Control.md)
Описывает процесс валидации токена при каждом запросе:
- Извлечение и проверка токена
- Валидация срока действия
- Загрузка данных пользователя
- Установка контекста безопасности
- Компоненты системы проверки доступа
- Диаграмма последовательности операций

## 🔑 Принципы безопасности

### Stateless архитектура
- Сервер не хранит сессии
- Вся информация об аутентификации в токене
- Независимая обработка каждого запроса

### Token-based authentication
- UUID токены с криптографической стойкостью
- Хранение токенов в базе данных
- Ограниченный срок действия

### Bearer Token схема
- Стандарт OAuth 2.0
- Передача токена в HTTP заголовке Authorization

### Безопасное хранение паролей
- Криптографическое хеширование
- Автоматическое соление
- Необратимость преобразования

## 🔄 Жизненный цикл токена

```
1. Регистрация
   └─► Создание учетной записи с хешированным паролем
          ↓
2. Авторизация (Login)
   ├─► Проверка учетных данных
   ├─► Создание токена
   └─► Возврат токена клиенту
          ↓
3. Использование токена
   ├─► Токен в заголовке Authorization: Bearer <token>
   ├─► Проверка токена на каждом запросе
   └─► Доступ к защищенным ресурсам
          ↓
4. Истечение токена
   └─► Необходим новый Login
```

## 📊 Компоненты системы

### Слой API
- **Login Endpoint** - обработка входа пользователей
- **Protected Endpoints** - ресурсы, требующие аутентификации

### Слой Security
- **Authentication Filter** - фильтр проверки токенов
- **Token Provider** - извлечение и валидация токенов
- **Security Configuration** - конфигурация правил доступа

### Слой Services
- **Token Service** - управление жизненным циклом токенов
- **User Service** - работа с данными пользователей
- **Account Service** - работа с учетными записями

### Слой Data
- **Token Repository** - хранение токенов
- **User Repository** - хранение данных пользователей
- **Account Repository** - хранение учетных записей

## 🛡️ Безопасность

### Реализованные механизмы
- ✅ Хеширование паролей
- ✅ UUID токены (сложность 2^128)
- ✅ Ограниченный срок действия токенов
- ✅ Stateless архитектура
- ✅ ThreadLocal изоляция контекста
- ✅ HTTPS для защиты при передаче

### Рекомендации для улучшения
- 🔧 Механизм обновления токенов (Refresh Tokens)
- 🔧 Возможность отзыва токенов (Revocation)
- 🔧 Ограничение частоты запросов (Rate Limiting)
- 🔧 Двухфакторная аутентификация (MFA)
- 🔧 Привязка токенов к IP адресу или устройству
